# Forge CLI v0.4.0

Forge now keeps a project's source media, generated outputs, review evidence and
delivered versions in one local resource library. This release also brings WAV
audio delivery and a Windows x64 portable package alongside macOS Apple Silicon.

## Project resource libraries

- Scan selected folders, edit the intake JSON, and register source images,
  animations, audio and Packs with stable content identities.
- Search revisions and Pack members, compare versions in an offline gallery,
  and record separate technical, visual, auditory and license review assertions.
- Retain media in the project, select delivery versions, and use consumer resource
  locks to keep a game on explicitly chosen revisions.
- Register production outputs with recoverable publication records. Reuse exact
  historical outputs without another generation request.
- Transfer selected resources between macOS and Windows, rebind local roots,
  verify inventories and installations, and reconcile parallel catalog histories.

```bash
forge guide project-assets
forge project init --path ./library --name "Game resources" --local-assets --json
forge asset scan --project ./library --root ./source-media --out scan.json --json
forge asset register --project ./library --input scan.json --json
forge asset search --project ./library --json
forge asset preview --project ./library --out ./preview --json
```

Legacy catalogs migrate only after an explicit fingerprint-bound preview and
apply. Backups preserve their original bytes and historical Pack hashes. Older
CLIs cannot read the V3 library; keep a consumer's pinned executable until its
upgrade is verified. Review assertions describe a particular revision and do not
automatically approve later versions or establish third-party license rights.

## Audio and native delivery

Import local WAV music, sound effects and ambience into audio Packs and native
Godot streams. Processing retains source identity and reports technical checks;
listening review remains explicit. ACE-Step and Stable Audio 3 are optional
external tools: discovery is read-only, and Forge does not bundle, install or
start their models. Run `forge guide audio` for the workflow.

This release also includes source locks, portable delivery receipts, installed
resource audits, static native canvases and matte processing, layered Packs and
Godot playback/preview support. Native installation uses the existing ownership,
content-drift and rollback checks. Character animation remains experimental;
advanced character and world-asset commands remain optional source features.

## Install on macOS Apple Silicon

Download `forge-installer.sh` from this release:

```bash
FORGE_VERSION=v0.4.0 sh forge-installer.sh
forge --version
forge doctor --json
forge guide
```

The macOS package remains unsigned and not notarized. Previous installed
versions are retained for rollback; upgrading the CLI does not automatically
update a separately installed skill or a game's toolchain lock.

## Install on Windows x64

The Windows package is **experimental and unsigned**. It is built and tested on
a real GitHub-hosted Windows runner, including PowerShell 5.1, fresh installation,
reinstallation, upgrade from an actual historical CLI, and native Godot delivery.

Download these four files from this release into one directory:

- `forge-x86_64-pc-windows-msvc.zip`
- `forge-x86_64-pc-windows-msvc.zip.sha256`
- `install-windows.ps1`
- `windows-package-common.ps1`

```powershell
$archive = Join-Path $PWD 'forge-x86_64-pc-windows-msvc.zip'
$expected = (Get-Content -LiteralPath "$archive.sha256").Split(' ')[0]
& .\install-windows.ps1 -Archive $archive -Sha256 $expected
& "$env:LOCALAPPDATA\GameSpriteForge\bin\forge.cmd" doctor --json
& "$env:LOCALAPPDATA\GameSpriteForge\bin\forge.cmd" guide
```

The installer needs no administrator rights and does not edit PATH. Windows can
read the embedded guide; optional `skill install` remains macOS/Linux only.
See the [Windows package guide](https://github.com/MightyKartz/GameSpriteForge/blob/v0.4.0/docs/releases/windows-portable.md)
for custom locations, Godot configuration and rollback.

Both platforms bundle FFmpeg/FFprobe with checksums and corresponding source and
license files. Install Godot 4.6.x separately; native acceptance uses 4.6.3.
`release-verification.json` records the two archive/binary hashes and their common
version and source commit. macOS additionally retains the existing SBOM and
artifact attestation. The shared release is published only after both native
builds, installed-package checks and paired identity verification succeed.
