# Forge CLI v0.7.0

**Resource processing, diagnostics and reliable delivery for AI agents.**

Forge's direct users are Codex and other coding agents. This release improves
how they turn existing or generated images, animation frames and audio into
Godot resources, diagnose bad inputs and recover from failed delivery. Creative
generation and game logic remain with the agent and its chosen tools.

## What changes for agents

- **Lossless sprite delivery:** flat animation/character and icon/prop PNGs receive
  explicit Godot import settings that preserve stored RGBA. Installation checks
  the saved native textures against the Pack and rolls back on mismatch. Existing
  texture filtering, shared coordinates, anchors and frame timing remain explicit.
  Look for `godot_lossless_sprite_import` in `doctor --json`; this policy does not
  extend to layered/world textures.
- **Actionable frame diagnostics:** pixel reports identify empty, edge-touching
  and duplicate frames with issue types, severity, certainty, zero-based frame
  indices, report pointers and correction options. Edge contact and repeated
  frames may be intentional; warnings are not automatic artistic rejection.
  Malformed image/audio inputs identify the item and source path; animation
  layout/timing errors identify the relevant action, frame or field.
- **Review and correction:** the existing offline original-PNG preview supports
  zoom, anchor reference lines and shared-time comparison of versions. Agents can
  replace a specified source frame in a new preparation request and revalidate;
  unchanged frames/timing and old evidence stay independently checkable. A blocked
  local animation can no longer write a misleading accepted review record.
- **One documented delivery flow:** embedded guides cover animation, static assets
  and audio using existing Plan/Job/Pack/install mechanisms. The delivery example
  now accepts `prepare-audio` with explicit channels and sample rate. Installation
  failure can be retried from the retained Pack; no regeneration is necessary.
  Audio library previews correctly recommend the auditory review domain.

Use the selected executable's `forge guide`, `forge guide animation-example`,
`forge guide animation`, `forge guide audio` and `forge guide local-delivery-example`.
No new orchestration framework or automatic animation generation is introduced.

## Compatibility and upgrade

Use the recommended installer for your platform in the download table. The eight
release attachment names and the optional source/notices bundle remain compatible
with v0.6.4 automation. See [downloads](downloads.md) and
[Windows installation](windows-portable.md).

Updating Forge does **not** update a consumer project's toolchain lock, previously
installed resources or a separately installed Codex skill. Keep existing verified
pins; select the new executable explicitly in an isolated project, verify the
resources and only then approve that project's upgrade. Reinstallation applies
the new sprite import policy to the targeted resources. Existing source assets,
Pack history and review evidence are preserved; new candidates require their own
applicable review. Audio request defaults remain unchanged; use explicit output
format fields when preserving the source format matters.

## Verification and limitations

M1–M3 source changes passed native macOS/Windows checks with Godot 4.6.3 and 4.7.2.
This version's release gate additionally requires the actual packaged public
launchers, fresh installation, reinstall, v0.6.4 upgrade, bundled FFmpeg/FFprobe
and M2/M3 workflows on both native platforms. Historical upgrade coverage remains.
The tag-triggered workflow publishes only after both package jobs and paired
archive verification pass. See the [release verification record](../qa/release-v0.7.0.md).
Source CI is not a substitute for installed-package verification.

Default features remain empty. Character/world optional source workflows are not
promoted into the default release. Animation preparation remains experimental:
structural/native checks do not certify artistic quality, listening, licenses,
automatic pose generation or game readiness in every project. M4 real-project
paired benefit observations are pending; this release makes no measured claims
about saved agent time or reduced model costs. Generation costs and local
processing remain separate.

macOS Apple Silicon and experimental Windows x64 remain the release targets.
Godot 4.6.x or 4.7.x is installed separately. Packages are unsigned and macOS is
not notarized. Source media and external tools retain their own license conditions.

## 中文说明

**v0.7.0：面向 Agent 的资源处理、诊断与可靠交付。**

Forge CLI 的直接使用者是 Codex 等 Agent。Agent 理解需求、创作素材并编写游戏逻辑；
Forge 负责可重复的加工、诊断、验证和 Godot 交付。

- 平面动画/角色及图标/道具 PNG 使用明确的无损导入设置，保存后核对原生 RGBA，
  不一致则回滚。坐标、锚点、时序和采样设置继续明确保留；该策略不覆盖分层/世界纹理。
- 空帧、触边、重复帧报告包含类型、严重度、确定性、零起算帧索引及修正建议；
  有意触边或停顿不能自动当作美术错误。损坏图片/音频及布局/时长错误更容易定位。
- 既有原始 PNG 预览支持缩放、锚点参考和多版本同步对比；指定输入修正后产生新候选，
  保留历史证据。被阻塞的本地动画不能写入误导性的“已接受”记录。
- 嵌入 guide 统一动画、静态与音频流程；交付示例支持显式声道/采样率的音频准备。
  安装失败可从原 Pack 重试，音频预览推荐正确的试听审核域。

沿用 8 个发布附件和既有安装入口，不新增通用编排或自动动画生成系统。升级 CLI 不会
自动修改消费项目锁、已交付素材或单独安装的 skill；先在隔离副本验证，再单独批准
游戏工具链升级。原素材、历史 Pack 和审核记录保留，音频默认参数不变。

发布门槛覆盖 macOS/Windows 原生安装包、新装、重装、从 v0.6.4 升级、公共启动器、
内置 FFmpeg/FFprobe 与 M2/M3 场景，保留历史升级检查。双平台包与附件核验成功后才
发布。Godot 4.6.3/4.7.2 源码矩阵与实际安装包验证分别记录，不能互相冒充。

默认特性为空，高级角色/世界功能仍为可选源码能力，动画准备仍属实验性。技术通过
不代表美术、试听、许可或真实项目收益通过；M4 实测尚未完成，不宣称已节省 Agent
时间或模型费用。平台、签名状态与外部素材许可边界保持不变。
