# Forge CLI v0.7.1

**Resource library discovery, preview manifests and requirements reconciliation for AI agents.**

v0.7.1 is an additive patch over v0.7.0. It makes the local resource library
answer an agent's two recurring questions cheaply: what do I already have, and
what is still missing. All v0.7.0 delivery, diagnostics and preview behavior is
unchanged; existing catalogs, locks, receipts and review evidence carry over
without migration.

## What changes for agents

- **Vocabulary before guessing:** `forge asset tags` lists the kind/tag/purpose
  vocabulary already in use, with asset and revision counts, so agents compose
  exact filters instead of guessing spellings. It reads catalog metadata only:
  no media bytes are read and no index cache is created or repaired.
- **Cheap search for large libraries:** `forge asset search --metadata-only`
  skips source-byte verification and reports `status:"unknown"`. It is rejected
  when combined with `--status`, and verified searches remain the default
  everywhere else. Pack member lists come from recorded source metadata.
- **Preview media manifest:** `forge asset preview` responses and `preview.json`
  now carry a `media` array naming each revision's copied files with
  preview-relative paths, original labels and an image/audio/video type, so
  agents can open exact revision media without walking the output directory.
  Animation player frames are included; missing sources stay in `issues`.
- **Requirements reconciliation:** `forge asset check-requirements` compares a
  declared batch (`schemas/asset-requirements.schema.json`, example in
  `examples/asset-library/requirements.json`) against the library using the
  verified search contract. Each entry reports `covered`, `needs_review`,
  `incomplete` or `missing` with up to five hits; a missing `icon_set`/`prop_set`
  entry includes a pre-filled local static request skeleton with TODO
  placeholders. The command is read-only, performs no generation or Provider
  call, and `covered` describes inventory and recorded review state, not
  visual or license approval.

New capability IDs in `doctor --json`: `project_asset_vocabulary`,
`project_asset_metadata_search`, `project_asset_preview_media_manifest` and
`project_asset_requirements_check`.

## Compatibility and upgrade

Use the recommended installer for your platform in the download table. The
eight release attachment names and the optional source/notices bundle remain
compatible with v0.6.4 automation. See [downloads](downloads.md) and
[Windows installation](windows-portable.md).

Updating Forge does **not** update a consumer project's toolchain lock,
previously installed resources or a separately installed Codex skill. Existing
search, preview, review, selection, lock and installation contracts are
unchanged; the new flags and report fields are additive. Requirements batches
are inputs, not stored state; matches per requirement are evaluated in search
order and capped at 1000. Suggested request skeletons are starting points:
their TODO license and path placeholders must be completed before planning.

## Verification and limitations

Windows package gates (fresh install, reinstall, historical upgrades, bundled
helpers and installed asset-library workflows) passed on the merged commits.
Rust unit/integration coverage includes the vocabulary, metadata-only search,
preview manifest and all four reconciliation statuses with synthetic fixtures.
Offline CLI contract scripts assert read-only behavior and zero Provider
requests. See the [release verification record](../qa/release-v0.7.1.md).

Default features remain empty. The reconciliation report is not semantic
search, does not persist requirement batches, and does not infer tags,
generators or lineage at registration. Animation preparation remains
experimental; structural checks do not certify artistic quality, listening,
licenses or game readiness. This release makes no measured claims about saved
agent time or reduced model costs.

macOS Apple Silicon and experimental Windows x64 remain the release targets.
Godot 4.6.x or 4.7.x is installed separately. Packages are unsigned and macOS is
not notarized. Source media and external tools retain their own license
conditions.

## 中文说明

**v0.7.1：面向 Agent 的资源库发现、预览清单与需求对账。**

v0.7.1 是 v0.7.0 之上的增量补丁，让本地资源库低成本回答两个常见问题：库里
已经有什么、场景还缺什么。交付、诊断与预览行为不变，既有目录、锁、回执与
审核证据无需迁移。

- `forge asset tags` 列出在用的 kind/tag/purpose 词表和计数，先查词表再组合
  精确过滤；纯元数据读取，不触碰媒体字节、不创建索引缓存。
- `forge asset search --metadata-only` 跳过字节核验并如实报 `unknown` 状态，
  与 `--status` 互斥；已核验搜索仍是所有既有路径的默认。
- 预览响应和 `preview.json` 新增 `media` 清单，逐个版本列出复制媒体的相对
  路径、原始标签和类型（含动画播放器帧），缺失源仍只进 `issues`。
- `forge asset check-requirements` 按已核验搜索语义把需求批与库存对账，输出
  `covered`/`needs_review`/`incomplete`/`missing`；缺失的图标/道具需求附带
  预填的本地静态请求骨架（TODO 占位）。只读、零 Provider 请求，`covered` 不
  等于美术或许可批准。

升级 CLI 不修改消费项目锁、已交付素材或单独安装的 skill；新参数与报告字段
均为增量。单需求匹配按搜索排序最多评估 1000 条。发布门槛沿用双平台安装包
验证；默认特性为空，不做语义搜索、需求批持久化或登记时自动推断标签。
平台、签名状态与外部素材许可边界保持不变。
