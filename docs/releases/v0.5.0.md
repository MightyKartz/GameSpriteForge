# Forge CLI v0.5.0

Forge can now configure Godot and help coding agents verify and export a game,
alongside its existing image, animation, audio and project resource-library workflows.
macOS Apple Silicon and experimental Windows x64 packages share this release.

## Godot setup and project requirements

Select an existing Godot 4.6.x installation once per machine:

```sh
forge setup godot --path /absolute/path/to/Godot --json
forge doctor --json
forge guide godot-workflow
```

macOS accepts `Godot.app` or its executable; Windows accepts the official console
executable. Forge stores the path, version and executable hashes locally. A changed
configured engine fails validation instead of silently switching to another copy.
Command-specific selection and `FORGE_GODOT_PATH` take precedence over saved setup.

Alternatively, `forge setup godot --download --json` explicitly downloads the
SHA-512-pinned official standard Godot 4.6.3 editor. Add `--templates` to download
the export templates as well. Templates are a separate large download; existing
incomplete or unrecognized template directories are preserved and reported.
Godot and its templates are not bundled in the Forge archives.

`forge godot lock --project /absolute/game --json` creates a portable project lock
for the Forge package version and full Godot version. `forge godot check` verifies
the selected tools. Asset installation respects that lock, and changing the lock
invalidates a previously prepared installation plan.

## Verify and export a game

```sh
forge godot verify --project /absolute/game --output /absolute/qa/run-1 --json
forge godot verify --project /absolute/game --output /absolute/qa/view-1 --screenshot --json
forge godot export --project /absolute/game --preset "Desktop" --output /absolute/qa/build-1 --run --json
```

Create the output parent first; each output directory must be new and outside the
source game. Verification imports an isolated snapshot and runs its main scene.
Optional screenshots use actual rendering; project-specific interaction tests can
be supplied with `--acceptance-script`. Logs and reports distinguish completion,
errors, early exits, timeouts and cancellation.

Each run uses a fresh child-process profile for normal `user://` data, including
custom user directories. Existing saves and source settings remain unchanged.
This is working-copy and profile isolation, not a sandbox for untrusted game code.

Export uses an existing preset for the host desktop platform. Standard and custom
release templates are resolved before profile isolation; relative custom paths
are bound only in the copied preset. The template and output hashes are recorded.
`--run` launches the actual exported program for a bounded headless startup check.
Cross-target export, distribution signing and device acceptance remain part of
the game's own delivery workflow. Runtime success is not visual/gameplay approval.

## Install and upgrade

On macOS Apple Silicon, download `forge-installer.sh` from this release and run:

```sh
FORGE_VERSION=v0.5.0 sh forge-installer.sh
forge --version
forge doctor --json
```

On Windows x64, download the ZIP, its `.sha256` file, `install-windows.ps1` and
`windows-package-common.ps1` into one directory:

```powershell
$archive = Join-Path $PWD 'forge-x86_64-pc-windows-msvc.zip'
$expected = (Get-Content -LiteralPath "$archive.sha256").Split(' ')[0]
& .\install-windows.ps1 -Archive $archive -Sha256 $expected
& "$env:LOCALAPPDATA\GameSpriteForge\bin\forge.cmd" doctor --json
```

Packages are unsigned; macOS is not notarized. Windows remains experimental.
Both packages include FFmpeg/FFprobe and their license/source notices. The
paired release verification records their common version and source commit.

Existing game pins, receipts and installed Codex skills are not updated automatically.
The v1 project lock pins the Forge package version, not its Git commit or Cargo
features. Preserve a game's working toolchain until its upgrade is verified; use
`godot lock --update` only when explicitly accepting new toolchain requirements.
Character animation remains experimental. External model services may charge
separately; Forge's local processing does not generate model requests.

v0.5.0 在现有图片、动画、音频和资源库能力上，新增 Godot 配置、项目工具链锁定、
隔离验收和本机桌面导出。可选择已有引擎，或显式下载校验固定的 Godot 4.6.3；
导出模板需要单独选择下载，不会随 Forge 安装包自动安装。

验收在独立项目副本及存档环境中执行，支持真实渲染截图、交互断言、超时和取消，
保留日志与结构化报告。导出沿用项目预设，正确解析外部相对模板路径，并可启动实际
导出程序检查。运行成功不代表已完成美术、玩法或真机验收。

macOS Apple Silicon 与实验性 Windows x64 同步发布。安装包尚未签名，macOS 尚未公证。
升级不会自动改变游戏已有工具链锁、素材回执或单独安装的 Codex skill；请先验证再接受
新版本要求。完整操作可通过 `forge guide godot-workflow` 离线查看。
