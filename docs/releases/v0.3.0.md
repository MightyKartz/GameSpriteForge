# Forge CLI v0.3.0

The release candidate brings artwork made with Codex or other tools into Forge's
local PNG → Pack → Godot workflow. It supports **macOS Apple Silicon** with
**Godot 4.6.x** installed separately. Character animation remains experimental.

## Create assets with your preferred image tool

- Import transparent PNGs directly with `forge plan prepare-static`, as icon or
  prop sets. No Provider login or generated Style Lock is needed.
- Preserve original source files and hashes while normalizing canvas size,
  choosing nearest/linear sampling, and controlling faint alpha residue bounds.
- Deliver static textures, prop scenes, stable item paths and ground anchors to
  Godot using the existing ownership and rollback flow.

## Preserve existing animation

- Keep the source frame canvas and shared anchor with `preserve_source`.
- Carry rendering settings and nonuniform frame durations into native Godot
  resources. Apply explicit whole-sheet transparent padding/offset before slicing;
  reject operations that would discard any nontransparent pixel.
- Keep preserved coordinates during automatic repair. Anchor/canvas changes
  require manual review rather than silently repositioning individual frames.

Structural checks and successful installation do not establish art approval.
Prototype animation stays a prototype. GIF previews still use uniform FPS; use
Godot to review exact frame timing. Codex's image generation remains an external
source step; zero Forge Provider requests does not mean generation has no usage.

## Identify the executable

`forge doctor --json` now reports compiled Git commit/dirty state, target, build
profile, enabled optional Cargo features, and stable capability IDs. Missing Git
identity is represented as `null`. This distinguishes a source build from another
binary with the same version string. Release checks compare this identity with
the installed payload's `BUILD_INFO.json` and verify bundled helper selection.
The macOS public launcher follows its symlink to locate the versioned payload,
so a separate FFmpeg installation is not needed.

## Installation and compatibility

To try the candidate, use its release installer explicitly:

```bash
FORGE_VERSION=v0.3.0-rc.2 sh forge-installer.sh
```

The stable installer continues to select the latest stable release while the
candidate is being validated. Existing version directories are retained for
rollback. Binaries are **unsigned and not notarized**; archives include checksum
manifests, SBOM/attestation and the corresponding bundled FFmpeg source.

The default CLI build remains `default = []`. Subject/Character V2, world assets
and game-art manifest workflows still require optional source-build features.
This release does not add a Windows binary or restore desktop/MCP distribution.

The release workflow exercises local static and animation contracts against the
actual fresh/upgrade installation, using synthetic sources and native Godot
resources. Consumer asset replay is recorded separately in the
[integration report](https://github.com/MightyKartz/GameSpriteForge/blob/main/docs/qa/forge-local-assets-integration-2026-09-08.md).
Follow the [local asset guide](https://github.com/MightyKartz/GameSpriteForge/blob/v0.3.0-rc.2/docs/automation/codex-local-assets.md) for requests
and [forge-use](https://github.com/MightyKartz/GameSpriteForge/blob/v0.3.0-rc.2/.agents/skills/forge-use/SKILL.md) for agent usage.
