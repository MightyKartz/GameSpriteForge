# Forge CLI v0.3.0

Forge v0.3.0 brings artwork made with Codex or other tools into the stable local
PNG → static Pack → Godot workflow. It supports **macOS Apple Silicon** with
**Godot 4.6.x** installed separately. Character animation remains in development
and testing.

## Create assets with your preferred image tool

- Import transparent PNGs directly with `forge plan prepare-static`, as icon or
  prop sets. No Provider login or generated Style Lock is needed.
- Preserve original source files and hashes while normalizing canvas size,
  choosing nearest/linear sampling, and controlling faint alpha residue bounds.
- Deliver static textures, prop scenes, stable item paths and ground anchors to
  Godot using the existing ownership and rollback flow.

Follow the [local PNG guide](https://github.com/MightyKartz/GameSpriteForge/blob/v0.3.0/docs/automation/codex-local-assets.md) to prepare your
first set. Static `game_ready` means structural checks passed; review the artwork
at gameplay scale before accepting it. Codex's image generation is a separate
source step; zero Forge Provider requests does not mean image generation has no
usage.

## Installation and compatibility

Download `forge-installer.sh` from the [v0.3.0 release](https://github.com/MightyKartz/GameSpriteForge/releases/tag/v0.3.0), then select this version explicitly:

```bash
FORGE_VERSION=v0.3.0 sh forge-installer.sh
forge --version
forge doctor --json
```

The regular installer selects the latest stable release; prereleases require an
explicit version. Existing version directories are retained for rollback.
Binaries remain **unsigned and not notarized**. Release packaging includes
checksums, `BUILD_INFO.json`, SBOM/attestation and corresponding bundled FFmpeg
source.

v0.2.1 predates `plan prepare-static` and the new local animation request fields.
When upgrading a game with a pinned CLI, verify the contracts it requires before
updating the toolchain lock for future imports. Keep existing asset receipts and
their source history unchanged. If you re-import assets, create new receipts for
those results. Local static revisions use a new request; targeted item retry and
asset-project catalog registration are not part of this local importer.

## Identify the executable

`forge doctor --json` reports the compiled build identity in `data.build` and
supported contracts in `data.capabilities`. Use these alongside the binary
SHA-256 to identify the CLI used for an import. Git identity is `null` when it is
unavailable, such as in a source archive. Runtime Godot/FFmpeg availability is
reported separately.

## Still in development

Character generation, animation reuse and directional workflows remain
experimental. v0.3.0 includes local animation options for preserving source
coordinates, rendering settings and frame timing, but their availability does
not establish production or visual approval. GIF previews still use uniform FPS;
review exact timing in native Godot resources. The directional reuse helper is
source-only and is not installed by the CLI installer.

The default CLI build remains `default = []`. Subject/Character V2, world assets
and game-art manifest workflows still require optional source-build features.
This release does not add a Windows binary or restore desktop/MCP distribution.

Release verification covers fresh and upgrade installations with synthetic local
static and animation sources and native Godot resources. Validation results and
consumer asset replay are recorded separately in the
[integration report](https://github.com/MightyKartz/GameSpriteForge/blob/main/docs/qa/forge-local-assets-integration-2026-09-08.md).
Follow the [local asset guide](https://github.com/MightyKartz/GameSpriteForge/blob/v0.3.0/docs/automation/codex-local-assets.md) for requests
and [forge-use](https://github.com/MightyKartz/GameSpriteForge/blob/v0.3.0/.agents/skills/forge-use/SKILL.md) for agent usage.
