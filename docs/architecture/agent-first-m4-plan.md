# Agent 使用效率与可靠交付：M4 实施计划

日期：2026-09-21。状态：定位与观测协议实施；**真实收益尚未验收**。
承接[资源生产路线图](agent-resource-production-roadmap.md)，不是新的产品或编排框架。

## 1. 决策与本轮范围

用户明确：Forge CLI 的直接使用者是 Agent，全部开发与服务以帮助 Agent 更好地开发
游戏为目的。开发者定义目标、提供必要授权并按任务参与创意审核，不需要学习 Forge
内部流程。CLI 帮助、guide、诊断、预览、安装与恢复应支持 Agent 独立推进真实任务。

原 M4 的“人工任务与设置时间节省 20%”不适合作为主要门槛。正式配对尚未开始，
本轮将新观察切换到 [agent-delivery-v2](../qa/asset-delivery-comparison.md)：
以同一验收下的 Agent 任务与设置耗时为主指标，自主完成率和交付正确性为约束，
重试、临时脚本、文档查找、费用、维护和非预期人工介入解释收益来源。
人工时间保留为辅助指标。v1 与历史结果归档，不重新解释历史 PNG 计时。

本轮只提交产品描述、实施计划、版本化对照协议和观测模板。既有能力足以开始任务
发现，不新增 CLI 命令、JSON 运行协议或通用调度器，不改嵌入 guide 的发行能力描述。
后续代码或 guide 改动必须由观察中确认的 Agent 阻塞驱动。

## 2. 已核实候选及排除项

以下来自 2026-09-21 本机只读检查，不是配对实验结果。消费项目正被其他工作修改，
真正开始实验前重新冻结提交、未提交文件清单和素材哈希；本轮不复制私人素材到 Forge。

| 候选 | 当前证据与意义 | 下一步及不应作的推断 |
| --- | --- | --- |
| Survival 急救图标区分 | `game/experiments/route_v2/screen.gd` 的准备图标映射将两种急救准备映射到 medkit；既有评审要求小尺寸可区分。适合静态加工、预览、局部修订和引擎集成 | 冻结两种用途及真实卡片尺寸；基线可直接用原生导入。区别可以通过游戏 UI 徽标实现时，不强制生成新图或引入 Pack |
| Survival 旧攻击帧 | 周野短刃原图有少量紫边；四帧可见下缘约相差 25 px，是对齐审核线索，不是自动判定坏帧。默认主流程已用状态立绘 | 仅在仍使用全身动画的真实任务中纳入。不要为满足动画样本数把旧流程重新接入主线 |
| Survival 音效 | `game/ui/combat_audio.gd` 以确定性 PCM 合成弩、刃、防护、治疗音效 | 没有 WAV 文件不等于缺音效；未经试听不提出替换整套音库。其合成输出不能当作 M4 真实外部音频任务的替代样本 |
| Sword 音频来源恢复 | 迁移清单 SHA 与记录一致；`audio/output` 对应 563 条历史文件在记录位置缺失，其他分组只做存在性核对。素材库验证器实际因缺失文件失败 | 搜索明确的归档/备份并按原 SHA 找回，不能认定永久丢失或归因 Forge。只有索引无原件时如实记录不可恢复；不重新生成冒充原件 |
| Sword 当前音频交付 | `validate_audio.py` 与正确入口 `validate_project_music.py` 通过；后者返回母曲 PCM 未重查、无新解码 | 旧 `validate_music.py` 是冻结历史依赖，对 v6 报 requests 错误不属于当前入口故障。不要改旧工具破坏来源哈希。现有通过不证明源文件可重建、试听或许可批准 |
| Sword 新动画 | 贯虹等已有原图、锚点、安装证据及游戏消费路径 | 尚未确认必须重做的动画缺陷；源图放大边缘不能替代游戏尺寸播放判断。等待实际需求，不批量补帧 |

这些发现足以定义候选任务，不足以证明 Forge 已节省 Agent 工作。缺失文件可能是
存储/归档问题；如果已有工具能解决，就不修改 Forge。Godot 显示位置、数字遮挡和
战斗规则属于游戏实现，除非证明确由 Forge 交付错误引起，否则不计为 Forge 缺陷。

## 3. 依赖顺序与 PR

每个实施阶段使用一个 Goal；每次只推进一个 PR，开发或文档变更完成后自审、修复、
本地验证及适用 CI，通过后合并，再开始下一 PR。没有实测缺口就不创建功能 PR。
用户已授权的隔离核对自主执行；真实任务目标、外部生成费用或生产安装授权缺失时，
给出具体待决定事项。对照计划本身不升级消费项目锁，也不授权发布私人素材。

| 阶段 | 工作与交付 | 完成条件 / 依赖 |
| --- | --- | --- |
| A：本轮协议 PR | 中英文定位对齐；v1 归档；v2 协议、模板及此计划；路线图同步 | 链接、JSON、指标定义及历史保留检查通过；PR 自审与适用 CI 完成。只完成计划，不勾选 M4 |
| B：真实任务预注册 PR | 重新核对 Survival/Sword 当前状态；明确用户目标与任务是否仍需要；在隔离副本冻结输入、项目、模型/权限、工具、顺序、预算、验收与日志采集方法 | 每对开始前完成注册。缺少源件时先登记真实恢复目标；找不到原件不能启动依赖原件的加工。无真实动画需求时保留动画覆盖缺口 |
| C：按任务顺序观察 | 首先选择已确认的 Survival 静态识别任务、Sword 来源恢复任务；按实际需求产生后续修订与再集成。保存两组全部尝试、时间事件与诊断 | 每个任务对照独立验收；不能把同一任务三次运行算三轮。观察数据先保留，确认 Forge 缺陷才开最小修复 PR；记录修复/维护成本并以新观察验证，不覆盖旧失败 |
| D：证据与投入决策 PR | 汇总各项目和各任务流的成功率、自主完成率、主指标、成本限制、维护与实际复用；更新路线图 | 两项目各至少三轮真实任务；完整 M4 还需真实动画交付→局部修正→再集成覆盖。按 v2 给继续投入、收缩或暂缓结论；覆盖不足保持 M4 待验，不用新的功能代替证据 |

阶段 C 可以分成多个顺序 PR，但不预设功能清单。阶段 B 不能把候选发现包装成已完成
对照，阶段 D 也不能仅靠新协议过关宣称 M4 完成。当前图标与恢复候选不自动凑足六轮。

## 4. 任务合同与记录落点

新记录复制 [v2 模板](../qa/artifacts/delivery-comparison-v2-template.json)，使用独立 cohort
及任务 ID。详细度随任务变化，不建立产品级新协议。预注册至少明确：

- 真实需求来源、源素材/项目快照、两组工具版本、模型配置及上下文隔离。
- 游戏侧验收：图标在目标尺寸的区分要求、像素/alpha 与路径；动画共享坐标和时序；
  音频原件哈希、处理参数和循环；恢复以找回匹配原件及实际可消费为准。
- 每组相同预算与停止条件；失败、拒绝、人工介入及创意审核的处理方式。
- 原始事件起止、工具失败与重试、脚本变更、独立 native Godot 检查和结果位置。
- 生成与加工分账；历史生成成本未知即 null，零 Provider 请求不等于生成免费。

固定源素材交付和包含生成的任务分开统计；前者先衡量 Forge 处理价值，后者在存在真实
生成需求且权限具备时再做。合理的拒绝属于安全结果，但未交付资源时不能算成功率。
视觉、试听、技术、许可的审核者和证据各自记录，必要审核不可为提高自主率而取消。

M4 汇总报告放 `docs/qa/`，精选脱敏观测放 `docs/qa/artifacts/`。原始媒体、日志、
私有工程和账号用量证据留本地，不从工具调用次数推算 token 或账单。

## 5. 验证及当前状态

本轮仅文档及未测模板：检查本地链接、JSON 可解析性、两组字段一致、未测值没有伪造
零值；核对 v1 模板与已提交历史证据未改；不需要 Rust/Godot 构建。后续修改嵌入 guide
必须重建对应二进制并做 guide 检查；修改 Godot 交付必须做真实引擎验证。平台结论只
覆盖实际执行的平台，macOS 通过不代表 Windows 通过。
