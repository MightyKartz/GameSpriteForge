## 1. 定位与开发意义

**Forge 是面向 AI Agent 的游戏资源生产工具，把生成或已有的图像、动画帧和
音频，处理、验证并交付为可直接使用的游戏引擎资源。首要支持 Godot。**

直接使用者是 Codex 等 Agent，最终受益者是游戏开发者。Agent 负责理解需求、
生成原始素材、选择方案、判断观感和编写游戏逻辑；Forge 负责重复、精确、
可验证的资源处理。人工审核按任务需要参与，不要求开发者理解内部协议。

核心价值需要通过实际任务证明：Agent 使用 Forge 后，应减少临时脚本、反复
诊断、人工修正和集成错误，同时承担更少的使用与维护成本。命令数量、结构化
报告数量、成功生成 Pack 或通过单元测试，都不能单独证明产品价值。

English positioning: **Forge is a game-resource production tool for AI agents.
It prepares, validates and delivers generated or existing images, animation
frames and audio as engine resources, starting with Godot.** Agents own intent,
creative generation and game logic; Forge provides precise processing and
verifiable delivery. Animation production is the first development priority;
updates and recovery are underlying guarantees. Planned capabilities are not
claims about the current default release.

## 3. 调研结论与边界

调研日期为 2026-09-21。以下是官方文档核对，不是付费生成效果或生产成功率实测。

| 对照对象 | 已描述的能力 | 对 Forge 的决策影响 |
| --- | --- | --- |
| [SpriteCook](https://www.spritecook.ai/docs/guide-create-character) | 角色生成、修订、多动作预览和导出 | 不重复建设完整生成平台 |
| [SpriteCook 帧编辑](https://www.spritecook.ai/docs/guide-frame-editor) | 关键帧参考、重排、定向重生成 | 局部修正需要成为闭环，但无需自行承担模型生成 |
| [SpriteCook Godot 集成](https://www.spritecook.ai/works-with/godot) | SpriteFrames、TileSet 和地形配置 | “能导出 Godot”不是独有优势 |
| [SpriteCook UI 资源](https://www.spritecook.ai/godot-ui-theme-generator) | Theme、StyleBoxTexture 和九宫格边距 | 暂缓为扩充列表而增加 UI 生成系统 |
| [Agent Sprite Forge](https://github.com/0x0funky/agent-sprite-forge) | Agent 生成、后处理和场景交付 | 必须与可复用 Skill 对照，不能假定 Agent 每次从零写脚本 |
| [sprite-gen](https://github.com/aldegad/sprite-gen) | 动画整理、图集、预览与审核 | 参考闭环设计，比较实际返工成本 |
| [Pixel Snapper](https://github.com/Hugo-Dz/spritefusion-pixel-snapper) | 像素网格与调色板处理 | 先评估现有工具，避免重复实现通用算法 |

SpriteCook 的 [分辨率说明](https://www.spritecook.ai/blog/why-ai-cant-match-pixel-art-resolution)
也记录了生成姿态时像素网格变化导致的失败。Forge 应提供可核查的诊断，不承诺
通过裁切、缩放或对齐修复模型缺失的姿态与细节。

接入外部工具时核实具体接口与模型：[Pixel Engine v1.5 公告](https://www.spritecook.ai/blog/pixel-engine-v1-5-sprite-animation-model)
与 [通用 API 文档](https://www.spritecook.ai/api-docs) 的帧数、尺寸限制存在差异。
不把网站文案固化为永久能力，也不据文档缺失断言竞争产品没有某功能。

## 4. 优先完成的用户任务

### 主任务：现有素材成为可用角色动画

用户请求示例：“把这些角色帧整理成 Godot 可播放的 idle、walk、attack，保留
人物比例和落脚点；有坏帧就指出位置，修好后再交付。”

闭环：Agent 提供素材与约定 → Forge 检查和处理 → Agent 检查预览及诊断 →
Agent 调用外部生成工具修正或补帧 → Forge 重新验证 → 交付并在 Godot 中验证。

第一阶段支持明确布局的图集和独立帧序列。不规则图集先诊断并允许指定裁切区域，
自动识别只有在真实案例和可靠性证据足够时才扩大范围。缺少帧序或动作划分时，
允许提出候选供 Agent 确认，不能静默猜测后标记成功。

### 配套任务

- “把这段音乐和这些音效导入 Godot，保留原始文件，说明格式、时长和循环设置。”
- “把这批图标或道具按约定画布与锚点整理并安装。”
- “只替换攻击动画的坏帧，保留已经验收的其他动作及游戏侧配置。”

简单且已符合要求的 PNG 可直接使用 Godot 原生导入。资源库、历史和回执按
复用、诊断与恢复需要启用，不应成为每个一次性任务的前置负担。

## 5. Agent 接口原则

| 原则 | 实施要求 |
| --- | --- |
| 能力可发现 | 复用随二进制发布的 guide、doctor 能力标识及任务示例，区分可选特性 |
| 输入明确 | 明确像素单位、坐标原点、帧索引、时间单位、默认值及不支持的输入 |
| 约定最小化 | 复用已有 request/Pack 字段，先补缺口，再决定是否需要版本化新字段 |
| 诊断可行动 | 返回稳定问题类型、动作/帧位置、证据路径、严重程度和修正选项 |
| 不掩盖不确定性 | 区分确定性错误、启发式提示、未验证项目及观感审核结果 |
| 输出可检查 | 提供简短摘要、机器可读结果与按需读取的预览/详细报告，避免每次全量输出 |
| 支持局部迭代 | 修正产生新候选；未修改帧保持像素与时序，旧批准不自动继承到新候选 |
| 执行可恢复 | 延续任务身份、状态查询、失败恢复和来源记录，避免重复启动已完成工作 |
| 外部生成可区分 | Agent 的图像生成不是 Forge 本地处理；记录已知来源，不伪造 Provider 证据 |

诊断示例是“attack 第 7 帧触及右侧画布边界，需审核是否裁切；可扩大共享画布
或重新生成该帧”，而不是没有解释的质量分数。触边、重复帧和位置变化不必然
错误：武器伸展、停顿与跳跃可能是有意动作，需要结合约定判断。

## 6. 实施阶段与验收

以下为依赖顺序，不承诺日历工期。各阶段完成后再根据实际工作量和验收结果
确定下一阶段范围。除兼容性与已知缺陷修复外，不提前铺开后续功能。

### M0：能力盘点与基准任务

- 从当前默认发行版和源码分别盘点动画、静态素材、音频、预览及安装能力。
- 对照实际代码、测试与 guide，列出“已有可复用、需修复、确实缺失、可选实验”四类。
- 选择一套经授权的真实角色素材，以及公开或合成的回归素材；固定原图、帧序、
  时长、共享坐标和目标引擎约定。音乐和音效各选一个样例。
- 记录 Agent 完成任务的调用序列与卡点；基线允许使用现有 Skill 和长期复用脚本。

**交付：**能力差距表、独立于 Forge 格式的任务验收、样例清单、首轮观察记录。
**通过条件：**确定第一个真实阻塞点；不存在“因为没有某命令所以新增命令”的待办。
**阻塞处理：**若暂缺第二个独立游戏项目，可继续技术验证，但产品收益结论保持证据不足。

### M1：角色动画端到端交付（最高优先级）

- 复用已有本地动画入口，覆盖规则图集和帧序列；补足 M0 确认的输入缺口。
- 保留或显式转换共享画布、帧区域、原点、逐帧时长、动作名称与循环设置。
  不默认逐帧居中、缩放、镜像、插帧或改变动作速度。
- 输出透明 PNG/图集及已有 Pack/Godot 动画资源，连接现有预览与安装机制。
- 核对保存后的 SpriteFrames 内容与实际播放：帧区域、顺序、时长、循环、锚点
  及纹理设置符合约定。资源能加载与动作观感通过分别记录。
- 更新 Agent 任务示例，让正常任务不要求用户手工编写内部计划或资源清单。

**通过条件：**idle、walk、attack 三类动作完成同一闭环；非均匀时长、透明软边、
宽武器动作和明确共享锚点均有覆盖；无隐式像素/时序改变，错误输入有明确诊断。
无真实运行时证据的结果不能标记为完成引擎验证；无视觉审核不能宣称动作自然。

### M2：诊断、审核与局部修正

- 优先实现确定性检查：缺帧、非法帧区域、时长错误、空帧及输出与约定不符。
- 再根据真实返工案例增加边界接触、重复姿势、帧间位置/尺度变化及循环接缝提示。
  足部接触和身份一致性若只能估计，应返回不确定性，不能自动判定通过。
- 扩展现有预览：原尺寸播放、逐帧、明暗背景、基准线及修正前后同步比较。
- 支持显式替换选定帧或修改时序/偏移的最小修正配方，复用现有任务与数据结构。
- Agent 按诊断选择本地修正或外部重生成；Forge 接收修正结果并重跑受影响检查。

**通过条件：**故意植入的缺帧、裁切、时长等缺陷能被发现；有意停顿、跳跃不会
被强制修复；修正一个动作不改动其他已验收动作；预览与 Godot 使用同一份时序约定。
**范围限制：**先解决实际坏例，不建立通用动作评分模型或全功能动画编辑器。

### M3：音频与静态素材统一使用体验

- 复用本地 WAV 音乐/音效导入与原生 Godot 音频资源，统一任务摘要和错误表达。
- 检查格式、时长、声道、采样率和现有循环元数据；转换必须显式且保留源文件。
  不默认归一化音量、降混声道或裁切；其他输入格式按需求单独评估。
- 静态素材沿用已有图标/道具画布、锚点和采样方式约定；复用动画阶段的诊断表达。
- 在 guide 中提供三条最短任务路径：动画、音乐/音效、图标/道具；复杂字段按需读取。

**通过条件：**三类任务都能被 Agent 发现、执行、检查与恢复；音乐和音效在 Godot
中正确加载播放，循环元数据经核对；试听结论与技术检查分开。缺少本地依赖时给出
明确原因，不为一次导入自动安装模型或下载权重。

### M4：真实项目验证与发布决策

- 在 Survival 及另一个独立维护的游戏项目中各完成至少三轮配对任务，第二个项目
  在 M0 确认。包含首次动画生产、局部修正、再次集成；配套覆盖音频和失败恢复。
- 两组采用同样的源素材快照与游戏验收；一组使用 Agent＋现有工具，一组使用
  Agent＋Forge。尽可能固定模型配置，生成结果存在随机性时保留全部尝试。
- 分开测量“固定源素材的加工交付”和“包含生成的完整任务”，不混淆模型差异与
  Forge 收益。两组允许复用脚本，不要求基线复制 Forge 的内部格式。
- 只把已验证路径晋级为稳定支持；更新中英文产品描述、嵌入 guide、能力标识及
  发布说明。默认功能与可选源码特性继续分开。

**通过条件：**达到第 8 节的技术与收益门槛。若未达到，修复实际瓶颈或收缩到
有证据的工具能力，不以增加更多功能代替验证。

## 7. 建议 PR 拆分与实施落点

| 批次 | 范围 | 主要位置与前置条件 |

| PR-A | M0 盘点、任务验收与可提交回归素材 | `docs/qa`、`scripts`；先确认素材可公开 |
| PR-B | M1 输入和坐标/时序缺口 | `packages/core`、`packages/pack`、`schemas`；仅补 PR-A 确认的缺口 |
| PR-C | M1 Godot 交付及 Agent 最短路径 | `packages/cli`、现有 Godot helper、`forge-use`；依赖 PR-B 必需部分 |
| PR-D | M2 可行动诊断、对比预览和局部修正 | 现有处理器与预览组件；先提交确定性检查，再评估启发式提示 |
| PR-E | M3 音频/静态体验一致性 | 已有导入、报告和 guide；不另建任务框架 |
| PR-F | M4 真实案例、原生平台验证和发布准备 | `docs/qa`、既有 CI 与发布流程；以实测决定发行范围 |

这是候选拆分，不要求六个 PR 全部产生代码。若盘点发现能力已存在，改进测试、
guide 或脚本即可。创建、审查、合并、发布按具体实施任务分别执行；本文不自动
创建 PR、升级消费项目的 CLI 或更改现有素材回执。

## 8. 验证与收益指标

技术检查复用 [开发验证指南](../../.agents/skills/forge-dev/references/verification.md)，
按影响选择动画、Pack、音频、CLI、安装事务与 native Godot 检查。修改嵌入 guide
需重建二进制；仅修改本文不需要 Rust 构建。运行证据记录提交、dirty 状态、特性、
doctor 身份、二进制哈希和 Godot 版本。原生 macOS 通过不能替代原生 Windows 验证。

| 指标 | 记录方式与用途 |
| --- | --- |
| 验收成功率 | 相同任务合同，保留失败与中断；不能只统计最终成功尝试 |
| 人工时间 | 分开记录设置、介入、修正、视觉/试听审核与维护 |
| Agent 工作量 | 记录工具调用、重试、临时脚本及无法自行解决的步骤；不把少调用直接等同于低费用 |
| 模型与服务成本 | 记录实际可得用量和账单；未知保留 null，不由调用次数推算 |
| 总耗时 | 分开记录生成、处理、引擎验证及无人值守等待 |
| 资源正确性 | 像素、坐标、时序、资源引用和失败恢复分别验收 |
| 观感 | 实际播放或试听审核，保留问题与修正次数；结构通过不能替代 |
| 维护与复用 | 两组都计入脚本/工具修复与学习成本，记录下一轮是否选择继续使用 |

沿用 [对照协议](../qa/asset-delivery-comparison.md) 的计算方式和初始产品门槛：
两个项目各至少三轮，各项目人工任务与设置时间的配对节省中位数至少 20%，没有
更多未解决交付失败，累计节省时间超过新增维护成本。该阈值是决策标准，不是结果。
Agent 指标用于定位收益来源，不能挑选某个下降的指标替代整体结论。

若基线人工时间为零，百分比无定义，应报告绝对时间、成本和正确性；产品门槛保持
证据不足，或在后续新一轮试验前明确修订标准，不在看到结果后更换胜出条件。

[已有 PNG 实验](../qa/focus-delivery-pilot-2026-09-21.md) 只证明简单导入存在额外开销，
既不能证明动画闭环无价值，也不能证明 Forge 已节省人力。缺少项目、费用或维护
记录时继续标为证据不足，不将“Agent 专用”作为免于验证的理由。

## 9. 暂缓范围与风险处理

- 暂缓新增通用生成平台、Agent 编排框架、桌面编辑器以及更多游戏引擎。
- 现有 Provider 保持兼容；新的服务接入先走标准文件交付，只有重复需求才增加适配。
- 不将自动补帧、骨骼生成、任意多方向一致性作为本计划默认交付。
- 暂不扩大碰撞框、攻击事件、复杂战斗动画状态机；游戏逻辑继续由 Agent 和游戏项目负责。
- 不为统一接口而迁移旧 Pack、改写历史批准、更新消费项目锁或削弱安装保护。
- 不复制第三方项目源码进入 Forge；外部算法/依赖先评估现有工具调用、维护成本与许可。
- 不把私人素材、凭据、原始 Agent 对话、Job 存储或运行缓存提交到仓库。

阶段风险包括原图本身不可用、启发式误报、协议复杂度增长、生成耗时掩盖处理收益，
以及多平台安装差异。分别通过明确拒绝原因、保留不确定性、优先复用现有字段、
拆分测量与原生平台验收处理。
